# Face Puppet

A single-module Android app that turns **any photo of a face** into a **2.5D live puppet** driven by the
front camera, rendered with OpenGL ES 3.0, with separate upper/lower teeth rows, stencil-clipped mouth
and eye layers, and MP4/PNG capture. Everything runs on-device: no network, no OpenCV, no NDK.

```
Kotlin 1.9.24 · AGP 8.5.2 · Gradle 8.7 · minSdk 26 · target/compileSdk 35 · GLES 3.0 · MediaPipe Tasks Vision 0.10.14
```

## 2. Build

```bash
# 1. Model assets (first build only, ~4 MB, needs network once)
./gradlew downloadModelAssets

# 2. Debug APK
./gradlew assembleDebug

# 3. Install + launch
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.facepuppet/.MainActivity
```

`downloadModelAssets` fetches:

| asset | source |
|---|---|
| `face_landmarker.task` | `https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/latest/face_landmarker.task` |
| `canonical_face_model.obj` | `https://raw.githubusercontent.com/google-ai-edge/mediapipe/master/mediapipe/modules/face_geometry/data/canonical_face_model.obj` |

`preBuild` depends on it **and** on `verifyModelAssets`, which fails with an actionable message when a file
is missing, and re-validates that the OBJ really has 468 vertices / 898 triangles so a truncated download
cannot silently produce an APK that dies with “Failed to create FaceLandmarker”. If the machine has no
network, drop both files into `app/src/main/assets/` manually and the task becomes a no-op.

No signing config is committed; `assembleRelease` needs your own keystore, `assembleDebug` is
signed with the debug key and installs immediately.

## 3. How the spec maps onto the code

| Spec | Where |
|---|---|
| 478 landmarks, hard-coded index groups | `rig/FaceRig.kt` (`LIPS_OUTER`, `LIPS_INNER`, eye rings, iris 468/473, nose 1, `FACE_OVAL`) |
| Region polygons from landmarks | `MouthLayer` / `EyeLayer` build fans in NDC from the projected warped landmarks |
| IMAGE-mode landmarking of the photo | `FaceLandmarkerEngine.detectPhoto` ← `PhotoIngest.ingest` |
| Umeyama `L → R` on a stable subset | `AlignmentSolver.solve` (subset `6,9,168,197,195,133,362,1`), closed-form 2D Procrustes |
| `D_i = s·Rot(θ)·L_i + t − R_i`, clamp 6 % IOD | `AlignmentSolver.residuals` (`RESIDUAL_CLAMP = 0.06` face units, i.e. 6 % of IOD) |
| yaw/pitch/roll from `facialTransformationMatrixes[0]` | `PuppetRenderer.extractAngles` (basis-vector `atan2`), clamped ±28/±20/±25° |
| OBJ → VBO/EBO, depth extrusion, skirt | `MeshBuilder.loadCanonical` + `MeshBuilder.build` (z compressed to 0.35 × face width, 36-quad skirt, rim shade = 0.55 × sampled colour = −45 %) |
| `pos = R_pose·(restPos + delta)`, then perspective | `Shaders.PUPPET_VERTEX` + `PuppetRenderer.computeMatrices` |
| Blendshape → vertex offsets, sparse matrix, 0 alloc | `FaceRig.DeformRig` (built once, `apply()` is one linear pass over ~700 entries into a reused `FloatArray`) |
| Stencil write → interior → upper teeth → lower teeth → tongue | `MouthLayer.draw` (single clear + `GL_LEQUAL` with negative Z bias) |
| HD teeth + mipmaps + anisotropy | `PuppetRenderer.uploadBitmap(..., anisotropy = true)` (`GL_LINEAR_MIPMAP_LINEAR`, `GL_EXT_texture_filter_anisotropic`) |
| Eye layer with blink/gaze, conditional compositing | `EyeLayer` (`|photoBlink − liveBlink| > 0.05` or `|gaze| > 0.05`) |
| 3 threads, latest-wins, interpolation | `CameraController` (analyzer) → `FaceLandmarkerEngine` (worker) → `PuppetRenderer` (GL); `PuppetState.latestFrame` is an `AtomicReference`, `updateInterpolation` blends the last two frames |
| Recorder (shared EGL, `eglPresentationTimeANDROID`) | `io/Recorder.kt` |
| Snapshot PNG | `PuppetRenderer.captureSnapshot` + `io/Snapshot.kt` |
| Button state survives rotation, stop on pause | portrait-locked activity handling config changes itself; `onPause` finalises the MP4 through a GL-thread handshake |

### Coordinate conventions (used consistently everywhere)

* MediaPipe: normalised image space, `x/y ∈ [0,1]`, origin top-left, **y down**.
* Face units: origin at the photo's face centre, +x right, **+y up**, +z towards the viewer, **IOD = 1**.
* The residual is computed in image space and its **y is negated** when it is added to the render-space
  delta; the selfie mirror is applied **once**, by negating the x row of the projection matrix, so all
  landmark arithmetic stays in raw camera space.
* NDC x and y are not isotropic, so the mouth/eye layers lay synthetic quads out in y units and divide
  the x extents back out by the viewport aspect (otherwise teeth are stretched on a 20:9 phone).

## 4. Acceptance criteria — where each one is satisfied

1. **API 26 and API 35, no crash; denial retry path.** No API >26 call is reachable without a version
   guard (`MediaStore.RELATIVE_PATH`/`IS_PENDING` → Q, `insetsController` → R, `layoutInDisplayCutoutMode`
   → P; `MediaMuxer(FileDescriptor)` is API 26). Denial shows the panel with *Grant camera* (re-request)
   and *Open settings*. A missing model asset finishes gracefully with a toast instead of throwing.
2. **Face detection on the photo, “No face found in that photo.”** `PhotoIngest.ingest` →
   `FaceLandmarkerEngine.detectPhoto`; `null` maps to `Result.NoFace` → `R.string.error_no_face_in_photo`.
3. **Head turn visible and clamped, no black holes at ±28°.** `extractAngles` → clamped in
   `computeMatrices`; the 36-quad silhouette skirt is drawn behind the face (depth test, stencil off) so a
   yaw shows a rim-coloured edge instead of the background.
4. **Jaw open reveals distinct upper and lower rows with a dark interior; teeth stay attached.** Both rows
   are anchored to inner-lip landmarks that are already deformed by the same `jawOpen` weights
   (`DeformRig`), the interior is a maroon gradient behind them, and the tongue sits between them in depth.
5. **Blink and smile within 100 ms.** 30 fps inference (33 ms) + one-frame interpolation; blink drives
   both the lid vertices and the `EyeLayer` opening, smile drives the lip corners.
6. **≥ 24 fps on a mid-range device with the GPU delegate.** Zero allocation in `onDrawFrame`, one
   `glBufferSubData` of ~6 KB per frame, five draw calls + two stencil clears, mipmapped face texture.
   Delegate choice is logged: `adb logcat -s FaceLandmarkerEngine`.
7. **Playable MP4 with the puppet composited; PNG snapshot.** `Recorder` (encoder surface in the *same*
   EGL context, re-rendered at encoder aspect with a re-projection pass) and `Snapshot` (offscreen PNG).
8. **No TODO, no unimplemented functions, no extra dependencies.** Only the five declared dependency
   groups are used; `androidx.core` is never referenced directly.

```bash
# 10 s of frame timing from SurfaceFlinger, then a histogram of frame durations
adb shell dumpsys gfxinfo com.facepuppet framestats | head -40

adb shell top -d 1 -o PID,%CPU,ARGS | grep facepuppet
```

## 6. Known limitations and their mitigations

Three things a single photograph cannot provide, and what the code does about each: **extreme yaw**,
because a flat photo has no side geometry to reveal, is hard-clamped to ±28° (pitch ±20°, roll ±25°) and
backed by the extruded silhouette skirt, so instead of smearing past the limit the puppet simply stops
turning and shows a rim-coloured edge; **an occluded or closed source-photo mouth** is handled by
measuring the photo's own inner-lip gap at load time — when it exceeds 0.08 × IOD the real upper and lower
teeth are cropped out of the photo into the atlases, and otherwise the two bundled 1024×256 strips are
used and revealed progressively, with the live blendshape coefficients (not the photo) driving how far
each row is exposed; **glasses** are the weakest case, since reflections and frames are baked into the
photo texture and the eye layer can be composited over a lens, so the eye layer is skipped entirely
whenever the photo and the live face agree on blink and gaze (letting the original painted eye through)
and `eyeWide`/`eyeBlink` are damped relative to the photo's baseline, which avoids the usual “iris
floating over a spectacle lens” artefact. Beyond those, a photo taken with a very open mouth keeps that
expression as its rest pose (the blendshape rig is additive on top of it, never subtractive), and
asymmetric photos are registered by a similarity transform that cannot un-rotate a face that was already
turned in the source image — both are mitigated by the Recenter button, which discards the interpolation
history and re-solves the registration from scratch.
